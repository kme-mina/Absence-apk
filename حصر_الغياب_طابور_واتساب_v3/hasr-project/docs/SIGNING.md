# توقيع التطبيق (Signing) — خطوات لمرة واحدة

⚠️ **هذه الخطوة يجب أن تتم على جهازك أنت، وليس هنا.** مفتاح التوقيع هو أهم سرّ في
هذا المشروع بالكامل — أي شخص يملكه يستطيع نشر تحديث لتطبيقك يبدو "رسمياً" لأندرويد.
لا تُشارك ملف `release.keystore` مع أحد، ولا تضعه داخل المستودع (`.gitignore` يمنع ذلك
افتراضياً، لكن لا تعتمد على ذلك وحده — انتبه بنفسك أيضاً).

## 1) توليد مفتاح توقيع حقيقي (مرة واحدة فقط، ثم احتفظ به للأبد)

يحتاج جهازك Java (JDK) مُثبَّتاً. نفّذ في الطرفية:

```bash
keytool -genkeypair -v -keystore release.keystore -alias hasr-release \
  -keyalg RSA -keysize 2048 -validity 10000
```

سيُطلب منك كلمة سر للـ keystore وكلمة سر للمفتاح (يمكن أن تكونا متطابقتين أو مختلفتين)،
وبيانات هوية شكلية (اسم، منظمة... يمكن كتابة أي شيء معقول). **احفظ كل من:**
- ملف `release.keystore` نفسه
- كلمة سر الـ keystore
- اسم الـ alias (`hasr-release` أعلاه)
- كلمة سر المفتاح

في مكان آمن (مدير كلمات سر مثلاً) — **إن فقدتها، لن تستطيع نشر أي تحديث مستقبلي لنفس
التطبيق؛ ستضطر لإصدار تطبيق جديد بمعرّف مختلف، وكل من ثبّت النسخة القديمة لن يحصل على
التحديث تلقائياً.**

## 2) إضافة الأسرار في GitHub (مرة واحدة)

في صفحة المستودع على GitHub: **Settings → Secrets and variables → Actions → New repository secret**،
أضف 4 أسرار بالضبط بهذه الأسماء:

| الاسم | القيمة |
|---|---|
| `KEYSTORE_BASE64` | ناتج الأمر: `base64 -w0 release.keystore` (على ماك/لينكس) أو `certutil -encode release.keystore tmp.b64` (ويندوز، ثم احذف السطرين الأول والأخير من الملف الناتج) |
| `KEYSTORE_PASSWORD` | كلمة سر الـ keystore |
| `KEY_ALIAS` | اسم الـ alias (`hasr-release` إن اتبعت المثال أعلاه) |
| `KEY_PASSWORD` | كلمة سر المفتاح |

## 3) بعد ذلك

كل `push` على الفرع `main` سيُنتج تلقائياً **نسخة APK موقَّعة حقيقية** جاهزة للتوزيع
(تجدها في تبويب Actions → آخر تشغيل → Artifacts → `hasr-alghiyab-release-apk-signed`).
بدون هذه الأسرار، يُبنى APK Debug فقط (صالح للاختبار الداخلي، **غير** صالح للتثبيت
على أجهزة العملاء دون تحذير أمني من أندرويد).

## تحديثات مستقبلية

استخدم **نفس** ملف `release.keystore` دائماً لكل تحديث لاحق لنفس التطبيق — أندرويد يرفض
تثبيت تحديث موقَّع بمفتاح مختلف عن النسخة المُثبَّتة أصلاً على جهاز المستخدم.
