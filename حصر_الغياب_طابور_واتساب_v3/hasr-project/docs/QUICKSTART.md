# دليل التشغيل الفعلي — خطوة بخطوة (مسار واحد فقط: مستودع خاص → APK → Google Drive)

هذا الدليل يشرح **مساراً واحداً فقط**، بلا بدائل وبلا GitHub Pages: مستودع GitHub
**خاص (Private)** → GitHub Actions يبني نسختي APK (تجريبية ومدفوعة) → تنزيلهما يدوياً
كملفات Artifact → رفعهما إلى Google Drive → مشاركة الرابط مع من تريد. كل خطوة أوامر
تكتبها حرفياً، وأزرار تضغطها بالاسم الظاهر أمامك فعلياً في الكود أو في واجهة GitHub.

**لماذا مستودع خاص لا يمنع أي شيء هنا:** بناء APK عبر GitHub Actions ورفع ملفاته
كـ Artifacts يعملان بالكامل على **GitHub Free حتى مع مستودع Private** — القيد الوحيد
هو عدد دقائق Actions الشهرية (موضَّح في نهاية هذا الدليل)، وليس حظراً على البناء نفسه.
هذا ما يختلف عن GitHub Pages (التي كانت تحتاج مستودعاً عاماً على الخطة المجانية)، وهذا
بالضبط سبب عدم استخدامها هنا بعد الآن.

---

## 0) إعداد لمرة واحدة: مستودع GitHub خاص

1. أنشئ حساباً على github.com إن لم يكن لديك.
2. اضغط **+** أعلى يمين الصفحة → **New repository**.
3. اسم المستودع: أي اسم إنجليزي بلا مسافات، مثال: `hasr-alghiyab`.
4. اختر **Private** (وليس Public — هذا هو الفرق الجوهري عن الدليل القديم).
5. **لا** تُفعِّل "Add a README file" (المشروع يحتوي واحداً بالفعل) → **Create repository**.
6. ستظهر لك صفحة بها أوامر جاهزة — افتح الطرفية (Terminal) داخل مجلد المشروع الذي فككت
   ضغطه، ونفّذ **بالترتيب**:

```bash
cd hasr-project
git init
git add -A
git commit -m "النسخة الأولى"
git branch -M main
git remote add origin https://github.com/<اسم-حسابك>/<اسم-المستودع>.git
git push -u origin main
```

(استبدل `<اسم-حسابك>` و`<اسم-المستودع>` بالقيم الفعلية). قد تُطلَب منك بيانات دخول
GitHub في أول `push` — اتبع التعليمات التي تظهر.

**تحقق من نجاح الرفع:** افتح `https://github.com/<اسم-حسابك>/<اسم-المستودع>` في
المتصفح — يجب أن ترى كل الملفات (src, docs, scripts...)، وفي الأعلى شارة تؤكد أن
المستودع **Private**.

> لا توجد خطوة إعداد إضافية لـ GitHub Actions — ملف `.github/workflows/build-apk.yml`
> موجود بالفعل في المشروع، ويبدأ العمل تلقائياً من أول `push` أعلاه.

---

## 1) الحصول على نسخة APK التجريبية (٣ أيام) كملف تُنزِّله

1. في صفحة المستودع على GitHub → تبويب **Actions** أعلى الصفحة.
2. ستجد عملية اسمها **Build Android APK (Trial + Paid)** عملت تلقائياً بعد أول `push`
   (أو اضغط عليها يدوياً → **Run workflow** إن أردت إعادة البناء في أي وقت).
3. اضغط على آخر تشغيل لها → انتظر العلامة الخضراء ✅ (قد يأخذ البناء وقتاً — راجع
   الملاحظة الصادقة عن الوقت في نهاية هذا الدليل، فهو يبني نسختين في نفس التشغيل).
4. انزل لأسفل صفحة التشغيل إلى قسم **Artifacts** → ستجد:
   - **`hasr-alghiyab-TRIAL-apk`** ← هذا هو ملف التجربة (اضغط لتنزيله؛ يأتي كملف مضغوط
     يحوي `app-debug.apk` بداخله — فكّ الضغط لتحصل على ملف الـ APK الفعلي).
   - `hasr-alghiyab-PAID-debug-apk` (وربما `hasr-alghiyab-PAID-release-apk-SIGNED`
     إن أضفت أسرار التوقيع) ← هذه للنسخة المدفوعة، تخصّها الخطوة 3 أدناه.

**لا يوجد نشر على الويب هنا إطلاقاً** — فقط هذا الملف الذي نزّلته الآن إلى جهازك.

---

## 2) رفع النسخة التجريبية إلى Google Drive ومشاركتها

1. افتح drive.google.com وسجّل الدخول بحسابك.
2. اسحب ملف `app-debug.apk` (الذي فككت ضغطه من الخطوة السابقة) إلى أي مجلد تختاره —
   يُفضَّل إعادة تسميته أولاً إلى اسم واضح، مثال: `حصر_الغياب_تجريبي_3_ايام.apk`.
3. بعد انتهاء الرفع: زر يمين الفأرة على الملف → **Share** (أو **مشاركة**) → تحت "General
   access" اختر **Anyone with the link** → **Copy link**.
4. هذا هو الرابط الذي تُرسله لأي مُجرِّب (واتساب مثلاً). عند فتحه، Google Drive يعرض
   صفحة تنزيل للملف — يضغط المُجرِّب زر التنزيل، ثم يُثبِّت الملف على هاتف أندرويد (قد
   يحتاج تفعيل "التثبيت من مصادر غير معروفة" مرة واحدة — تحذير طبيعي من أندرويد لأي ملف
   APK خارج متجر Google Play، وليس خللاً في التطبيق).
5. بمجرد أول فتح للتطبيق على جهاز المُجرِّب، تبدأ عدّاد الـ٣ أيام تلقائياً على ذلك الجهاز
   تحديداً (راجع `docs/TESTING.md` للتوضيح الصادق حول حدود هذا العدّاد عند إعادة التثبيت).

---

## 3) بعد الشراء: بناء/تجهيز النسخة المدفوعة

### أ) نسخة اختبار فورية (Debug — للتأكد من عملها على جهازك فقط، غير صالحة للبيع)
من نفس صفحة Artifacts في الخطوة 1: نزّل **`hasr-alghiyab-PAID-debug-apk`** وافتحه
بنفس خطوات الرفع لـ Google Drive أعلاه، للتجربة الداخلية فقط.

### ب) النسخة الموقَّعة الحقيقية (الصالحة للبيع الفعلي للعملاء)
تحتاج إعداداً إضافياً **لمرة واحدة فقط**، تفاصيله الكاملة في `docs/SIGNING.md`، خلاصته:
1. تُنشئ مفتاح توقيع على جهازك (أمر `keytool` واحد، موضَّح بالكامل هناك).
2. تضيف 4 أسرار في: Settings → Secrets and variables → Actions → **New repository
   secret** (تعمل بشكل طبيعي تماماً على مستودع Private — لا قيد هنا).
3. بعدها، أي `push` جديد (أو **Run workflow** يدوياً) يُنتج تلقائياً
   **`hasr-alghiyab-PAID-release-apk-SIGNED`** بجانب نسخة Debug في نفس قسم Artifacts —
   **هذا هو الملف الذي تُرسله فعلياً للعملاء**، ليس نسخة Debug.
4. نزّله، ارفعه إلى Google Drive بنفس خطوات القسم 2 أعلاه (مجلد مختلف أو اسم واضح
   يميّزه عن نسخة التجربة، مثال: `حصر_الغياب_النسخة_المدفوعة.apk`)، واحصل على رابط
   المشاركة.

---

## 4) إصدار كود تفعيل لكل عميل

**شرط أولي لمرة واحدة:** إن لم تفعله بعد، افتح `src/admin.html` على جهازك (نسخة Admin،
محلياً في المتصفح) → تبويب **🔐 الترخيص** → بطاقة **🔑 مفاتيح التوقيع** → اضغط **🆕 توليد
مفتاح جديد** (يُخزَّن في متصفحك فقط). انسخ المفتاح العام الناتج والصقه في
`keys/public_key.txt` داخل المستودع، ثم `git add -A && git commit -m "..." && git push`
— هذا يجعل البناء القادم على GitHub يُضمِّن مفتاحك الحقيقي بدل المفتاح التجريبي
الافتراضي. (تفاصيل أوسع في `docs/ACTIVATION.md`.)

ثم، لإصدار كود لكل عميل:
1. بطاقة **🧾 إصدار كود تفعيل لعميل (APK)**.
2. **مرجع العميل**: رقم واتساب العميل أو اسم المدرسة (أي نص مميّز لك).
3. **سنة بداية العام الدراسي**: مثال `2026` (يُحسب تلقائياً 1 سبتمبر 2026 → 31 أغسطس 2027).
4. اضغط **🔏 إصدار الكود**.
5. يظهر الكود في المربع أسفل الزر، وفي "سجل الأكواد الصادرة" تحته (للمراجعة لاحقاً).
6. زر **📲 واتساب** بجانب اسم العميل في السجل يفتح واتساب برسالة جاهزة تحوي الكود —
   اضغطه وأرسل مباشرة.

---

## 5) الخطوات المتكررة لكل عميل جديد

بعد إتمام الخطوات 0-4 **مرة واحدة** (المستودع خاص، البناء يعمل تلقائياً، مفتاح التوقيع
الحقيقي مُضاف، رابط Drive للنسخة المدفوعة الموقَّعة جاهز)، لكل عميل جديد لا تحتاج سوى
**خطوتين فقط**:

1. **أصدر له كوداً** — الخطوة 4 بالكامل (إدخال مرجعه وسنته، ضغط "إصدار الكود").
2. **أرسل له**: رابط Google Drive لملف الـ APK الموقَّع (نفس الرابط لكل العملاء — تُرسله
   مرة واحدة لكل عميل جديد فقط، ليس لكل تجديد سنوي) + كوده الخاص (زر واتساب الجاهز).

العميل يفتح رابط Drive، يُنزِّل ويُثبِّت الـ APK، يفتحه، يلصق الكود مرة واحدة — وينتهي
الأمر، يعمل بلا إنترنت بعدها حتى تاريخ الانتهاء.

## المسار الكامل بنظرة واحدة

```
المشروع (حزمة ZIP)
   │
   └─→ [خطوة 0] git push إلى مستودع GitHub خاص (Private، مرة واحدة)
          │
          └─→ GitHub Actions يبني تلقائياً (لا يوجد GitHub Pages إطلاقاً):
                 │
                 ├─ [خطوة 1] hasr-alghiyab-TRIAL-apk  ──→ [خطوة 2] Google Drive ──→ رابط للمُجرِّبين
                 │
                 └─ [خطوة 3] hasr-alghiyab-PAID-debug-apk (اختبار داخلي)
                        │
                        └─ hasr-alghiyab-PAID-release-apk-SIGNED (بعد SIGNING.md مرة واحدة)
                               │
                               └─→ Google Drive ──→ رابط ثابت للنسخة المدفوعة
                                      │
                                      └─→ [خطوة 4] إصدار كود لكل عميل
                                             │
                                             └─→ [خطوة 5] كرِّر (رابط Drive الثابت + كود جديد) لكل عميل جديد
```

## ملاحظة صادقة عن تكلفة ووقت GitHub Actions (مستودع Private)

- **الدقائق الشهرية:** حساب GitHub Free يمنح **2000 دقيقة Actions شهرياً** لأي مستودع
  Private (هذا رقم مؤكَّد من وثائق GitHub الرسمية، وليس تقديراً). المستودعات العامة
  (Public) لها دقائق غير محدودة، لكننا هنا اخترنا Private عمداً، فهذا الرقم هو الحد
  الفعلي الذي يهمّك.
- **وقت التشغيل الواحد:** لا يوجد لدينا رقم مقيس فعلياً من بيئة تنفيذ حقيقية لهذا
  المشروع بالضبط (هذا تشغيل فعلي داخل GitHub Actions، ولا تتوفر لنا بيئة مطابقة
  لقياسه مسبقاً هنا). التشغيل الواحد الآن يبني Gradle ثلاث مرات فعلياً (تجريبية Debug،
  مدفوعة Debug، ثم مدفوعة Release إن وُجدت أسرار التوقيع)، وهذا أطول من نسخة سابقة
  كانت تبني مرة واحدة فقط — **لا تفترض رقماً مُحدَّداً بالدقائق**؛ أول تشغيل فعلي لك
  على مستودعك هو المصدر الموثوق لمعرفة الوقت الحقيقي (يظهر أعلى صفحة التشغيل في تبويب
  Actions بعد انتهائه).
