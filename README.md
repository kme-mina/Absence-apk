# حصر الغياب والتواصل الذكي مع أولياء الأمور — نظام ترخيص APK موحّد

APK واحد لكل العملاء ← كود تفعيل موقَّع (Ed25519) فريد لكل عميل ← ربط بالجهاز عند أول
تفعيل ← تشغيل Offline بالكامل ← إنترنت فقط عند إرسال واتساب.

**مسار التوزيع الرسمي الوحيد المعتمد حالياً:** مستودع GitHub **خاص (Private)** →
GitHub Actions يبني **نسختين APK** (تجريبية ٣ أيام + مدفوعة) كملفات Artifact تُنزَّل
يدوياً → تُرفَع إلى Google Drive وتُشارَك روابطها. **لا يوجد GitHub Pages ولا أي نشر
على الويب في هذا المشروع.** التفاصيل العملية الكاملة في `docs/QUICKSTART.md`.

## هيكل المشروع
```
src/admin.html        نسخة Admin (المصدر الوحيد لكل شيء — منها تُبنى كل النسخ الأخرى)
keys/public_key.txt   المفتاح العام الحالي (يُضمَّن في كل بناء)
admin-tools/          مفتاح تجريبي للاختبار فقط — وَلِّد مفتاحك الحقيقي قبل الإنتاج
scripts/build-variants.js         يبني www/ (مدفوعة، APK) و www-trial/ (تجريبية ٣ أيام) من src/admin.html
scripts/write-capacitor-config.js يكتب capacitor.config.json بـ appId مختلف لكل نسخة (paid/trial)
tests/                 اختبارات آلية (تشغيل: npm test) — يشمل tests/test_trial.js لبوابة التجربة
docs/                  التوثيق (ابدأ بـ QUICKSTART.md، ثم ACTIVATION.md، ثم SIGNING.md)
.github/workflows/build-apk.yml   يبني نسختي APK (تجريبية + مدفوعة) تلقائياً كملفات Artifact
```

## كيف يعمل النظام (باختصار)
- **Admin** (`src/admin.html`, يُفتح في أي متصفح): يُولِّد زوج مفاتيح Ed25519 (خاص محلياً
  فقط + عام يُضمَّن في التطبيق)، ويُصدر كود تفعيل موقَّع لكل عميل (مرجع + تاريخ بداية/نهاية).
  في تبويب الترخيص بانر صريح يوضّح أن نظام APK/Ed25519 هو المسار الرسمي للبيع الآن، وأن
  نظام HTML+واتساب+كلمة سر القديم لا يزال يعمل تقنياً لكنه غير مستخدَم للبيع فعلياً.
- **APK المدفوع** (`www/`, appId: `com.hasralghiyab.app`, بُني عبر GitHub Actions من نفس
  الملف بلا أي أدوات مسؤول بداخله): يعرض شاشة لصق الكود عند أول تشغيل، يتحقق من التوقيع
  محلياً بالمفتاح العام فقط (بلا إنترنت)، يربط الكود بمعرّف الجهاز (`@capacitor/device`)،
  ويُعيد التحقق (توقيع + صلاحية + تطابق الجهاز) عند كل تشغيل لاحق.
- **APK التجريبي** (`www-trial/`, appId مختلف: `com.hasralghiyab.trial`, حتى يمكن
  تثبيته جنباً إلى جنب مع المدفوع على نفس هاتف الاختبار): بلا أي شاشة دخول، يعمل ٣ أيام
  من أول تشغيل فعلي على جهاز العميل، محسوبة عبر نفس سلسلة التخزين المُقوّاة (Android
  Keystore عبر SecureStoragePlugin أولاً). هذا رادع عملي يرفع تكلفة التحايل على مستخدم
  عادي، **وليس قفلاً مطلقاً** — راجع التوضيح الصادق في `docs/TESTING.md` حول ما يحدث
  فعلياً عند إعادة تثبيت كاملة بلا نسخة احتياطية.
- **التوزيع**: GitHub Actions يبني الاثنين في تشغيل واحد (Debug دائماً لكل منهما،
  وRelease موقَّعة للنسخة المدفوعة فقط إن أضفت أسرار التوقيع — راجع `docs/SIGNING.md`)
  كملفات Artifact تُنزَّل يدوياً من صفحة التشغيل، ثم تُرفَع إلى Google Drive للمشاركة.

## البدء السريع
1. `npm install && npm test` — تأكد أن كل الاختبارات تنجح (e2e + admin + trial).
2. اقرأ `docs/QUICKSTART.md` وطبّقه بالترتيب (مستودع خاص → Actions → تنزيل APK → Drive).
3. اقرأ `docs/SIGNING.md` لإنشاء مفتاح توقيع حقيقي قبل أي بيع فعلي (مرة واحدة).
4. اقرأ `docs/ACTIVATION.md` لطريقة إصدار وإرسال أكواد العملاء.

## حدود معروفة وموثَّقة (وليست مخفية)
- لا يمكن إلغاء ترخيص نشط فوراً عن بُعد بلا خادم — الإلغاء يتم بعدم التجديد عند الانتهاء
  (`docs/ACTIVATION.md`).
- الربط بالجهاز رادع قوي وليس ضماناً مطلقاً — أي حماية من جهة العميل فقط قابلة نظرياً
  للتحايل من مستخدم تقني على جهاز مفتوح الصلاحيات.
- الاختبارات هنا آلية بمحاكاة كاملة، وليست تشغيلاً على جهاز حقيقي — راجع `docs/TESTING.md`
  للتفاصيل والحدود بالضبط.
